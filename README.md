# AI Content Agency

هيكل أولي لوكالة محتوى تعمل بمساعدة وكلاء ذكاء اصطناعي، مع تفضيل الخيارات المجانية، وتسلسل واضح للمراجعة البشرية، وعدم النشر أو تنفيذ أي إجراء خارجي تلقائيًا.

## فكرة الشركة

يتعاون وكلاء متخصصون لتحويل موجز العمل إلى بحث ومسودة وخطة إنتاج وحزمة نشر قابلة للمراجعة. المخرجات اقتراحات وليست حقائق معتمدة؛ ينبغي التحقق من المصادر والحقوق والادعاءات قبل الاستخدام.

## الوكلاء

| الوكيل | الدور |
|---|---|
| CEO | يحدد الهدف ويخطط العمل ويوزع المهام ويراجع النتائج. |
| Researcher | يبحث ويجمع الأدلة ويميز الحقائق عن الافتراضات. |
| Scriptwriter | يصوغ نصوصًا ملائمة للجمهور والمنصة وأسلوب الشركة. |
| Producer | يحول النص إلى خطة مشاهد وأصول ومواصفات إنتاج. |
| Publisher | يجهز النسخ والوسوم وقائمة تحقق؛ لا ينشر تلقائيًا. |
| Governance | يراجع الخصوصية والحقوق والسلامة والشفافية. |
| Quality | يتحقق من الدقة والاتساق واللغة ومطابقة الموجز. |
| Memory Keeper | يقترح تنظيم الذاكرة وسجل القرارات دون تخزين الأسرار. |

تعليمات كل وكيل موجودة في `agents/`، والذاكرة وأسلوب الشركة في `memory/`.

## تسلسل النماذج

`config/company-config.json` هو مصدر الإعدادات. تتم محاولة مزود واحد في كل مرة وبالترتيب التالي؛ ولا يبدأ المزود التالي إلا بعد فشل السابق أو تعذر إعداده أو استخدام حصته:

1. **GitHub Models** — باستخدام رمز GitHub Actions وصلاحية `models: read`.
2. **Groq** — باستخدام السر `GROQ_API_KEY`.
3. **Gemini عبر Google AI Studio** — باستخدام السر `GEMINI_API_KEY`.
4. **مزود إضافي اختياري متوافق مع واجهة OpenAI** — باستخدام `OTHER_FREE_BASE_URL` و`OTHER_FREE_API_KEY` ومتغير `OTHER_FREE_MODEL`.

يطبق `scripts/run_agent.py` هذا الترتيب تسلسليًا، مع مهلة للطلب. إذا لم ينجح أي مزود، تنتهي المهمة بفشل واضح بدلًا من إنشاء نتيجة وهمية. لا تُحفظ المفاتيح في الملفات.

### إعداد الأسرار

من إعدادات المستودع **Settings → Secrets and variables → Actions**، أضف الأسرار المتاحة لديك:

- `GROQ_API_KEY`
- `GEMINI_API_KEY`
- اختياريًا: `OTHER_FREE_BASE_URL` و`OTHER_FREE_API_KEY` كأسرار، و`OTHER_FREE_MODEL` كمتغير Actions.
- يمكن تغيير أسماء النماذج عبر متغيرات `GITHUB_MODELS_MODEL` و`GROQ_MODEL` و`GEMINI_MODEL` عند الحاجة.

يوفر GitHub Actions الرمز `GITHUB_TOKEN`، ويطلب سير العمل صلاحية `models: read`. لا تضع المفاتيح في المستودع أو سجلات التنفيذ. المجانية والتوافر والحصص تخضع لشروط المزود وقد تتغير.

## سير العمل

- **Daily standup** (`.github/workflows/daily-standup.yml`): يعمل أيام العمل عند 09:00 UTC أو يدويًا، وينشئ موجزًا كـ artifact.
- **CEO orchestrator** (`.github/workflows/ceo-orchestrator.yml`): تشغيل يدوي بموضوع وجمهور، ويصدر خطة تنسيق كـ artifact.
- **Governance check** (`.github/workflows/governance-check.yml`): تشغيل يدوي لإعداد مراجعة حوكمة استشارية كـ artifact. تشغيله يدوي مقصود لتجنب تنفيذ كود مقدم في طلبات السحب غير الموثوقة.

تعتمد جميعها على `scripts/run_agent.py` لتطبيق سلسلة النماذج نفسها. النتائج تُرفع كـ artifacts ولا تُدفع تلقائيًا إلى المستودع ولا تُنشر خارجيًا.

## ملاحظات تشغيلية وأمنية

- المجانية ليست ضمانًا لحصة ثابتة أو توافر دائم؛ تحقق من شروط GitHub وGroq وGoogle الحالية.
- وجود مفتاح API قد يتطلب إعداد حساب أو تحققًا لدى المزود؛ المفتاح وحده لا يضمن تفعيل حصة مجانية.
- قد يتوقف GitHub Actions عند بلوغ حدود الاستخدام الخاصة بالحساب أو المستودع.
- الانتقال بين المزودين يعني مشاركة نص المهمة مع المزود البديل. لا ترسل معلومات سرية أو شخصية.
- النتائج الآلية تحتاج تحققًا بشريًا، خصوصًا المعلومات الحديثة والحقوق والادعاءات الحساسة. لا يوجد نشر آلي أو اعتماد قانوني.
